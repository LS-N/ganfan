# MVP 0.1 原型设计输入包

## 1. 产品名称

干饭 / 7 天身体拼图

## 2. 一句话定位

用一张标准餐食照和饭后 10 秒反馈，换取 7 天后的个人身体洞察。

## 3. 原型目标

验证用户是否愿意完成：

```text
建档
→ 饭前标准单拍
→ AI 即时结构分析
→ 饭后反馈
→ 7 天身体拼图报告
→ 餐前抽卡轻决策
```

## 4. 视觉要求

- Notion 风格
- 干净克制
- 移动端优先
- 信息层级清楚
- 低饱和
- 少装饰
- 决策导向
- 不制造焦虑
- 不像传统热量计算器

## 5. 页面清单

1. 欢迎 / 定位页
2. 建档页
3. 标准拍照页
4. AI 即时分析页
5. 饭后反馈页
6. 单餐档案页
7. 身体拼图报告页
8. 餐前抽卡雏形

## 6. 欢迎 / 定位页模块顺序

1. 产品标题
2. 7 天承诺
3. 每天要做什么
4. 非医疗和隐私提示
5. 开始建档按钮

## 7. 建档页模块顺序

1. 基础信息
2. 当前目标
3. 饮食预算 / 口味 / 忌口
4. 常见饭后感受
5. 保存按钮

## 8. 标准拍照页模块顺序

1. 餐食照规则
2. 示例构图提示
3. 拍照 / 选图入口
4. 图片预览
5. 重拍 / 提交分析

## 9. AI 即时分析页模块顺序

1. 分析进度
2. 结构判断
3. 风险提示
4. 轻建议
5. 置信度提示
6. 稍后反馈入口

## 10. 饭后反馈页模块顺序

1. 餐次提示
2. 饱腹状态
3. 身体感受
4. 价格满意可选
5. 保存反馈按钮

## 11. 单餐档案页模块顺序

1. 餐次标题
2. 餐食照片
3. 结构分析
4. 饭后反馈
5. 风险提示
6. 可选饭量校准入口

## 12. 身体拼图报告页模块顺序

1. 有效餐次数
2. 7 天规律
3. 风险组合
4. 安全食物
5. 下周建议
6. 餐前抽卡入口

## 13. 餐前抽卡雏形模块顺序

1. 今日餐前提示
2. 安全牌
3. 风险牌
4. 采纳 / 跳过按钮
5. 规则来源说明

## 14. 输出要求

原型必须包含：

- 页面结构
- 模块顺序
- 关键交互
- 空状态
- 错误状态
- 保存成功状态
- 拍照重拍和上传失败状态
- AI 分析加载、低置信度、失败兜底状态
- 饭后反馈未到时间、可反馈、错过状态
- 报告数据不足、可生成、已生成状态
