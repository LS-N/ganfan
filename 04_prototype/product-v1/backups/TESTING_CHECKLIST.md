# 三方案测试检查表

## 🧪 快速验证（5分钟）

### 步骤1：启动应用
- [ ] 服务器运行：`http://localhost:8765/meal-agent-product-prototype.html`
- [ ] 页面加载无报错（F12 Console 检查）
- [ ] 能看到底部四个 Tab（Today/计划/身体/Profile）

### 步骤2：模拟数据测试（无需 API）
1. 进入 Camera 页面
2. 点击 "选择图片" 上传任意食物照片（或不上传，直接用模拟）
3. 点击 "用模拟结果继续" 按钮

**验证方案一（两阶段）：**
- [ ] 立刻看到菜名（如"白切鸡饭" 或 "黄焖鸡米饭"）
- [ ] 看到 risk 徽章（低/中/高）
- [ ] 看到 3 条 detail 观察
- [ ] 看到 40 字建议
- [ ] 同时下方显示骨架屏："📋 餐食组成加载中…"

**验证方案二（精简 prompt）：**
- [ ] 骨架屏在 1-3 秒内被真实内容替换
- [ ] 营养卡片、食物组成、吃法建议都填充上去
- [ ] 没有页面抖动或重新布局

**验证方案三（流式）：**
- [ ] （需要真实 API）打开浏览器 DevTools → Network
- [ ] 观察 `/chat/completions` 请求是否为 `text/event-stream`
- [ ] 是否能看到逐个 SSE event 到达

## 🔑 真实 API 测试（需配置）

### 步骤1：配置 API
1. 进入 Profile 页面（底部 Profile tab）
2. 向下滑找到 "AI 真实分析配置" 卡片
3. 点击卡片，弹出 sheet：
   - **API Key**：粘贴你的 key（OpenAI / SiliconFlow 等）
   - **模型**：粘贴完整模型名（e.g. `gpt-4-vision-preview`, `Qwen-VL-Plus`）
   - **接口地址**：保持默认或修改为你的端点
4. 点击 "测试连接" → 看结果
5. 如果三个 ✓ 都过，点 "保存配置"

### 步骤2：上传真实食物照片
1. 回到 Camera 页面
2. 上传一张清晰的食物照片（最好有多样化食材）
3. 观察以下指标：

**时间指标：**
- [ ] 从上传到菜名出现：< 1.5s？（方案一）
- [ ] 从菜名到完整营养加载：< 5s？（方案二+一）
- [ ] 总完成时间：< 8s？

**精度指标：**
- [ ] 菜名识别是否正确？
- [ ] 营养评估（热量、蛋白、油脂）是否合理？
- [ ] 建议（吃多少、吃法顺序）是否实用？

**UI 体验指标：**
- [ ] 骨架屏转换到真实内容是否平滑（无闪烁）？
- [ ] 所有字段都能正常显示（没有 undefined 或缺失）？
- [ ] 按钮"好的，去吃了"能正常提交反馈？

## ❌ 如果遇到问题

| 症状 | 检查项 |
|---|---|
| 显示"模拟数据" | ① Settings 中 API Key 是否已保存？② Key 字段是否为空？③ 需要重新点一次"保存配置" |
| 菜名乱（显示错误菜） | 这是之前的 bug，已修复。刷新页面。 |
| phase1 后卡住 | ① 检查网络（F12 Network 是否卡在 phase2 请求）② 检查 API 额度是否用完 ③ Console 是否有红色错误 |
| 骨架屏一直显示 | phase2 超时。增加 timeoutMs 或检查 API 响应时间 |
| 图片压缩后识别差 | 这是权衡（速度 vs 精度）。可改为 `compressImage(imageUrl, 896, 0.8)` |
