# 干饭 · 分阶段成本模型 v1.0

> 商业基线文档。前提：**人力成本 = ¥0**（你 + AI Agent 完成开发/运维/客服/运营），只算真实现金流出。
> 配套：`subscription-plan.md`（订阅）、`break-even-monitoring.md`（盈亏监测）。

---

## 一、前提与口径

- **人力 = ¥0**：开发/运维/客服/运营全是 Agent + 你拍板，不发工资
- **只算现金流出**：AI 订阅、API 调用、服务器、存储、合规
- **开发成本** = 该 Phase 建设期月成本（含建设期 AI 调用）
- **运营成本** = 该 Phase 上线后的月度持续支出（随用户量浮动）
- 技术栈：React Native + Supabase + FastAPI + 硅基流动（SiliconFlow）AI

---

## 二、贯穿全程的 AI 团队底盘

无论哪个 Phase，"AI 团队"订阅是固定底盘：

| 项 | 月成本 | 说明 |
|---|---|---|
| Claude Code / 开发 Agent | ¥150–1,500 | 看用量，Max 档约 ¥1,400 |
| 运营 Agent API（客服/数据/增长） | ¥300–1,500 | 上线后才显著 |
| **AI 团队底盘小计** | **¥450–3,000/月** | 开发期偏低，运营期偏高 |

## 五、关键结论

1. **Phase 1-3 完全自付得起**（月成本 ≤ ¥8,000），靠几百付费用户滚动。"活下去"安全区。
2. **业务 AI 调用是唯一会失控的成本**——Phase 4 起占总成本 50-65%。保命手段从 Phase 1 写进代码：**限次 + 缓存 + 单次 embedding**。
3. **Phase 4 是真正门槛**——合规成本不能用 AI 省。跨过 Phase 4 前必须已有稳定付费现金流（≥¥1 万/月）。

---

## 六、滚动供养模型（无外部融资）

> 用 Phase 1-3 的低成本养出 300+ 付费用户和稳定现金流，再用这笔钱供养 Phase 4-6 的高成本。
> **每个 Phase 的运营利润供养下一个 Phase 的开发。** 进入下一 Phase 的前提 = 当前 Phase 已稳定盈亏平衡。
