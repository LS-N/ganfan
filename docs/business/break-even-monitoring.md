# 干饭 · 盈亏平衡监测系统 v1.0

> 商业基线文档。本系统由**数据 Agent** 每日自动运行，异常才告警用户。
> 配套：`subscription-plan.md`（订阅）、`cost-model.md`（成本）。

---

## 一、核心公式

```
盈亏平衡 = 月收入(MRR) ≥ 月总成本(月固定 + 月变动)

月变动成本 = 业务AI调用 × 活跃用户数   ← 唯一随用户线性涨的项
月固定成本 = AI团队底盘 + 服务器 + DB + 合规
```

盈亏平衡的本质是单变量方程：**每个用户的 AI 成本，必须低于他贡献的收入。**

---

## 二、最该盯的指标：单位经济（Unit Economics）

```
每付费用户月毛利 = 客单价(ARPPU) − 每用户AI成本 − 每用户基础设施分摊

> 0：用户越多越赚钱（健康）
< 0：用户越多死越快（危险，必须刹车）
```

| 示例（Phase 3） | 数值 |
|---|---|
| 付费客单 ARPPU | ¥30/月 |
| 每付费用户 AI 成本 | ¥3–6/月 |
| 每用户基础设施分摊 | ¥1–2/月 |
| **每付费用户毛利** | **¥22–26/月 ✅** |

同时算**免费用户拖累**：每个免费用户限次后约 ¥1–2/月 AI 成本，必须由付费用户毛利覆盖。这是"免费 AI 限次 + 缓存"的根本原因。

---

## 三、四个监测指标（数据 Agent 每日跑）

| 指标 | 定义 | 健康阈值 | 告警线 |
|---|---|---|---|
| ① 盈亏覆盖率 | MRR ÷ 月总成本 | ≥ 100% | < 80% 🔴 |
| ② 单付费用户毛利 | ARPPU − 单用户成本 | > ¥15 | < ¥5 🔴 |
| ③ 免费用户成本占比 | 免费用户AI成本 ÷ 总成本 | < 40% | > 60% 🟡 |
| ④ 付费转化率 | 付费用户 ÷ 总用户 | 2–5% | < 1.5% 🟡 |

## 五、Agent 自动响应规则（不经过用户）

| 触发条件 | 负责 Agent | 自动动作 |
|---|---|---|
| 覆盖率 < 80% | 增长 Agent | 加强转化钩子、推年费折扣 |
| 单用户成本飙升 | 运维 Agent | 查 AI 调用 bug / 缓存未命中 |
| 免费成本占比 > 60% | 架构 Agent | 收紧免费限次、强化缓存 |
| AI 月账单超预设上限 | 运维 Agent | **硬熔断 + 立即告警用户**（红线②）|
| 转化率 < 1.5% 连续 2 周 | 产品 Agent | 复查付费墙时机 / 价值感知 |

## 六、三级预警机制

只有红色打扰用户，其余 Agent 自己消化：

| 级别 | 条件 | 处理 |
|---|---|---|
| 🟢 健康 | 覆盖率 ≥ 100% | 数据 Agent 静默记录 |
| 🟡 预警 | 覆盖率 80–100% | Agent 自动优化，仪表盘标黄，**不打扰用户** |
| 🔴 危险 | 覆盖率 < 80% 或 AI 账单超限 | **立即推送用户**，附已采取措施 + 待拍板项 |

## 七、分阶段盈亏平衡基线

数据 Agent 用此表判断"当前是否健康"：

| Phase | 月成本基线 | 平衡所需付费用户 | 平衡所需 MRR |
|---|---|---|---|
| 1.0 | ¥1,500 | ~50 | ¥1,500 |
| 2.0 | ¥4,000 | ~135 | ¥4,000 |
| 3.0 | ¥6,000 | ~200 | ¥6,000 |
| 4.0 | ¥15,000 | ~500 | ¥15,000 |
| 5.0 | ¥30,000 | ~1,000 | ¥30,000 |
| 6.0 | ¥45,000 | ~1,500 | ¥45,000 |

> **进入下一 Phase 的门槛 = 当前 Phase 已稳定盈亏平衡。** 此规则写进架构 Agent 门控。

---

## 八、最小可埋监测（Phase 1 即落地）

1. **每笔 AI 调用记成本**：provider 返回 token → 折算 ¥ → 入库
2. **每个用户标 free/paid + 注册日**：算转化率与留存
3. **每天定时 Agent 汇总** → 输出仪表盘（复用现有"营养库巡检"定时机制）

有这三个，盈亏覆盖率即可每天自动算出。
