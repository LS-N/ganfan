## 主原型同步验收修订（2026-06-04）

本节同步首页状态机重构后的母版口径，优先级高于 2026-05-18 节中关于首页状态机的描述。

- 首页状态机按 4 态验收（优先级从高到低）：`DONE`、`PENDING_FB`、`DEFAULT`，`OVERDUE` 叠加在 DEFAULT 下方。
- `DONE` 态（已反馈）：反馈提交后 30 分钟内显示；内容为图片/占位 + 菜名 + 菜系 + 心情标签（图片右上角 overlay）+ 身体反应预测；30 分钟后自动过期回 DEFAULT。身体反应预测数据必须与反馈页「本餐反应预测」同源（A/B/C 三档降级逻辑），不得使用 `analysis.advice` 原始字段。
- `PENDING_FB` 态（待反馈）：今日有无反馈餐且距记录 < 30min；内容为图片/占位 + 菜名 + 菜系 + 「记录感受 →」主按钮；卡片下方有次级操作行（「+ 记录新一餐」描边按钮 + 「还没想好吃什么」文字链）。不显示身体预测、建议、营养详情。
- `OVERDUE` 提示：今日有无反馈餐且 ≥ 30min，叠加在 DEFAULT 主卡下方；不得替代主卡。单条显示缩略图（有图圆形裁剪/无图菜系 emoji 无盒子）+ 菜名 + 「未反馈」橙色胶囊按钮；多条默认收起为「X 餐未反馈 ▾」可展开；「未反馈」按钮直接进该餐反馈页，**不得跳转「我的记录」**。
- `DEFAULT` 态：其余所有情况；大点击区「记录这一餐」+ **全宽描边圆角按钮「还没想好吃什么 →」**（不得为纯文字链）；**首页默认卡不得出现「补录」按钮**。
- 无图占位：必须渲染带菜系 emoji 的浅橙色背景区域，高度与有图时一致；不得直接渲染纯文字头部。
- 「刚刚又吃了别的」入口已废弃，不得在待反馈卡或已反馈卡出现；加餐通过 DEFAULT 态「记录新一餐」入口独立记录。
- `_backfillMealId` 必须在 `renderHome()` 和 `startDirectMealRecord()` 入口清空，防止新餐反馈误覆盖旧记录。

## 主原型同步验收修订（2026-06-04 三状态页面重构）

本节为餐次三个页面的权威验收口径，优先级高于上文「分析页饭前结构」相关描述。核心：三页是同一份数据的三个视角，不得各自造字段。

**饭前·分析页**
- 渲染顺序：图片 → 餐食名称 → 副标题 → 餐食组成 → 建议 → 营养概览。
- 建议卡为「吃多少 / 怎么吃 / 少碰」三锚点，各管一件事、互不重复、不被截断（`reduceOrAvoid` 不得因合并截断而丢失）。
- 单食物且首项名称等于标题时，餐食组成不重复印菜名，主行显示「类别 · 份量」。
- 分析页**不得**出现「三条结构观察」和「可能饭后反应」；`advice` 不再作为独立卡渲染。

**饭后·总结页**
- **不得**出现「这一餐记完了 ✓」；主标题为菜名，副标题为 `场景 · 餐次 · 时间`。
- 实际摄入必须含蛋白/碳水/脂肪/**纤维**四条；数值 = 营养预估中值 × 实际摄入比例；拍照用 AI 图比例，未拍照按「吃了多少」比例。
- 本餐反应预测 A/B/C 三档与首页 DONE 态同源。

**回看·记录页**
- 整页为**一张卡 + 分界线**，不得拆成多个独立背景卡片。
- 分区顺序：基础信息（图 + 菜名 + 风险 + `场景·餐次·时间` + 饭后感受 + 实际吃了多少）→ 实际摄入（含纤维）→ 本餐反应预测 → 当时的饭前建议（折叠）。
- 饭后感受在副标题下一行直接显示，**只显示值 + emoji、不显示字段名**（饱腹/身体/满意度）。
- 记录页**不得**出现「三条洞察」（与实际摄入重复）和独立 `advice` 橙卡。
- 反馈与展示均**不再含「价格」**。

- 历史页第一个 Tab 按“饮食日历”验收，不再使用“打卡日历”；饮食日历应包含累计餐次总览、当月饮食餐次/记录天数、年月选择器、餐次筛选 Tab 和当日记录列表。

- 饮食日历日期格按当前月记录展示：无记录为灰色弱态；有记录只用当天已反馈餐次的综合反馈状态决定色块；待反馈不单独改变日期格颜色，必须在下方记录卡片中通过“补录反馈”表达。
- 当日记录标题按数量语义验收：未筛选显示 `D日 · Y 餐记录`，筛选后显示 `D日 · X / Y 餐记录`。
- 菜系地图按主原型真实地图资源验收：来源为 ECharts 4.0.2 `map/json/china.json` 的本地资产 `docs/prototype/assets/china-echarts-4.0.2.json` / `.js`，原型已实现 UTF8Encoding GeoJSON 解码、省级轮廓 path 渲染、按 `meal.province` 高亮和点击查看餐次。
- 菜系地图 Tab 内不再验收顶部标题区；真实 App 不应显示“美食版图”和“已解锁 X / 34 个省份菜系”两行，地图统计块保留在地图上方。
- 菜系地图不再验收圆圈标点；已解锁省份应以省级色块 + 中心 icon + 省份名称表达。菜系列表点击后应在同一容器展示该菜系时间轴，不跳新页、不在容器外追加详情。
- 菜系时间轴筛选按两个一级 Tab 验收：`全部时间` 展开年份和月份，`全部餐次` 展开早饭/午饭/晚饭/加餐；展开内容不得重复出现“全部时间 / 全部月份 / 全部餐次”。未筛选显示 `Y 餐记录`，筛选后显示 `X / Y 餐记录`。
- 真实 App 若要达到主原型省级 path 高亮效果，推荐引入 `react-native-svg` 并复用同一份解码/投影/省份映射逻辑；该路线需要用户单独批准新增原生依赖并重新打包。
- 若暂不新增原生依赖，App 只能验收为静态底图或中心点/点击区域降级方案，必须在任务记录中标记为 `PARTIAL`，不得写成已完成省级轮廓 path 高亮。
- 分析页营养库链路按真实接口验收，不再只看静态文案：主原型必须调用 FastAPI `GET /v1/nutrition/search?q=食物名&limit=5`，命中后展示“营养库匹配”、匹配项、置信度、单项营养贡献和汇总营养估算。
- 营养库接口不可用时必须显示“营养库未连接”并降级为 AI 估算，不得显示成已命中；未命中稳定标准项时显示“AI估算”；份量/规格不足时显示“待确认”。
- FastAPI 本地原型链路必须支持 `file://` 主原型和本地调试源跨源访问；生产部署时必须通过 `AI_SERVICE_CORS_ORIGINS` 收紧 CORS，不能把开发默认 CORS 当生产安全策略。
- 原型真实链路同步到 App 时，验收可复用 API 契约、字段、状态机和算法；不得把 HTML DOM、内联样式或浏览器专用实现当成 React Native 可直接复用代码。
- 分析页饭前结构按五块验收：餐次选择、图片、分析结果+建议、营养概览、打卡提示和按钮；不得恢复顶部重复菜系/场景/营养摘要、独立“进食建议”卡或饭前“可能饭后反应”结论。
- “分析结果+建议”卡必须合并菜名、结构点评、当前建议和餐食组成；菜系、地区、场景、食物数量只在餐食组成里表达。
- 建议来源标签按 `adviceStage` / `advice_stage` 或身体拼图状态降级显示，Phase 1 至少支持 `通用建议`、`反馈建议`、`身体拼图建议` 的展示与降级；后续阶段枚举 `身体结构建议`、`计划履约建议`、`食材记忆建议` 不得破坏当前渲染。
- 产品架构图可用横向滑动卡片表达六阶段建议成熟路径，但真实 App 不得直接复用 HTML 横向滚动和内联样式；应复用枚举、解锁条件、数据来源、示例文案和“记录 -> 反馈 -> 规律 -> 结构 -> 计划 -> 履约 -> 食材记忆 -> 下一轮建议”的链路。

## 主原型同步验收修订（2026-05-26 洞察引擎统一与消费层收敛）

本节同步 ##027～##030 完成后的原型口径，Phase 1 App 开发的 T5-02、T5-03、T5-04、T5-06 验收必须对照本节，优先级高于旧口径。

### deriveInsights 引擎统一（架构验收）

- 所有"对用户的判断"必须从 `deriveInsights(meals, phase)` 取数，不得存在孤岛算法
- `deriveInsights` 输出 5 类 angle（preference / avoid / reaction.bloated / reaction.drowsy / reaction.late_night），接口字段与原型 Insight 标准对象一致
- maturity 三档阈值（sparse/forming/mature）在 TypeScript 中以常量形式定义，不得硬编码在各消费函数内

### T5-04 首页新增验收项（深夜进食建议卡）

- 首页在 `isLateNightWithDinner() === true` 时显示非阻塞 advisory 卡（位于主卡上方）
- advisory 卡顶部标签为 `💡 建议（你可以忽略）`；无按钮，不阻塞任何操作
- 3 档渲染与 maturity 一致：mature → 具体"过去 N 次中 M 次不舒服"；forming → "规律正在显现"；sparse → "这是通用建议" + 3 个食物选项
- `startMealDecision` 和直接记录入口不再包含 `isLateNightWithDinner` 拦截；白天或无晚饭记录时卡片不显示（不占位）
- 旧 modal（`openLateNightAdviceSheet`）不得出现

### T5-06 身体拼图与时间轴新增验收项

**身体洞察叙事区块：**
- 拼图页 conclusion 区显示大叙事卡片（"你的身体说"标签），仅展示 mature 洞察
- 叙事文案包含具体食物例子（来自 sourceRefs 中的 dish 名）、百分比对比和底层机制解释
- forming 洞察不进入叙事区块
- 无 mature 洞察时叙事区块不渲染，不占位

**洞察成熟弹窗：**
- 提交反馈后，若出现新的 forming→mature 洞察，弹出一次性弹窗
- 按 `insight_celebrated_{id}`（App 用 AsyncStorage）去重，每条洞察只弹一次
- 与拼图解锁庆祝弹窗时序正确：拼图先（350ms），洞察后（1800ms）；无拼图时洞察 350ms

**成长时间轴洞察节点：**
- 时间轴节点除 5 个拼图节点外，支持洞察生命周期节点（🌱 浮现 / ✦ 成熟）
- 🌱 浮现：第 3 个样本时（amber 色）；✦ 成熟：第 5 个样本且 maturity===mature 时（accent 色）
- 无 mature/forming 洞察时，时间轴只显示拼图节点，无多余空节点

### T5-02 / T5-03 抽卡 insights 验收项

- body_puzzle 阶段 reason 文案必须引用具体 insight（"这是你的稳定偏好" / "避开了你已识别的触发词"），不得自由发挥个性化文案
- `PROMPT_CARD_RECOMMEND` 中存在"洞察硬约束"段落：必须基于列表，冷启动期"暂无"时禁止伪装个性化
- mature avoid 类菜系已被硬过滤（不出现在候选中）；preference 命中候选评分更高
- general / feedback 阶段 reason 不引用个人历史（测试：0 历史数据下 reason 无"根据你的偏好"类句式）

## 主原型同步验收修订（2026-05-26 档案页重构 + deriveInsights diet_structure_type）

本节同步 ##035 + ##036 完成后的原型口径，T4-05 和 T3-04 验收必须对照本节，优先级高于旧口径。

### T4-05 档案页三块结构验收

- 档案页只允许出现三块：干饭目标 / 身体拼图 / 干饭档案；旧的"基础信息"、"健康背景"、"AI状态"块不得出现
- 顶部副标题格式为 `N 餐记录`，不包含"看见阶段"或任何阶段名称文字
- 干饭目标两字段（goal + daily_budget）使用 flex 垂直排列，不横向并排
- 干饭档案不包含"记录餐次"独立字段，餐次数只在顶部副标题展示
- 偏好餐次三档验收：`< 5` 餐时显示"再记录 X 餐解锁"；`5–20` 餐时显示当前倾向文字 + `积累中` badge；`≥ 21` 餐时显示正式标签无 badge
- 干饭风格三档验收：`< 5 analyzed` 时显示"再记录 X 餐解锁"；`5–20 analyzed` 时显示 emoji + 风格名 + `积累中` badge + 数据量说明；`≥ 21 analyzed` 时显示 emoji + 风格名 + 基于 N 餐记录
- `diet_structure_type` angle 的 mature 阈值为 `analyzedN ≥ 21`（不是旧的 10），forming 阈值为 `analyzedN ≥ 5`
- 档案页打开时 deriveInsights 重算，响应无感知延迟（浏览器/App 均应 <20ms）
- goal/avoid/daily_budget 字段可编辑，修改后 `profiles` 更新

### T3-04 推送固定化验收

- 推送延迟固定为 **20 分钟**，不读取 `profile.reminder_delay_min`
- App 设置页不出现"反馈提醒时间"或任何推送延迟配置项
- 通知点击后正确跳转 feedback 页面

### T1-03 建档流程验收（更新）

- Q3（单日预算）完成后 `profiles.daily_budget` 写入整数，四档映射：60元以内→50，60\~120元→90，120\~200元→160，200元以上→250
- `meal_budget_weights` 写入 4 行初始默认值：早餐 20%、午餐 35%、晚餐 40%、加餐 5%
- `profiles.eatingStyle`（Q5）写入后台，档案页不显示此字段
- 建档后档案页展示 goal / avoid / daily_budget，不显示 age/gender/height/weight
