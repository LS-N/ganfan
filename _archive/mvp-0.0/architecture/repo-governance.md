# GitHub 仓库治理规范

## 1. 分支策略

```text
main       生产稳定分支
dev        日常开发分支
feature/* 具体功能分支
fix/*      Bug 修复分支
release/* 版本发布分支
```

## 2. PR 规则

所有代码必须通过 PR 合并。

PR 必须说明：

- 需求来源
- 修改范围
- 测试方式
- 是否影响热更新
- 是否需要重新打包

## 3. Issue 规则

所有 AI 任务都应转成 Issue 或任务单。

Issue 模板：

```text
目标：
背景：
输入文档：
开发范围：
不做什么：
验收标准：
测试要求：
```

## 4. 文档同步

开发任务完成后，需要同步更新：

- 相关 PRD
- 相关架构文档
- 任务拆解文档
- 发布记录
