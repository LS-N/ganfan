# MVP 0.1 原型评审表

## 1. 评审结论

- [ ] 通过
- [ ] 修改后通过
- [ ] 不通过

## 2. 欢迎 / 定位页评审

- [ ] 是否 10 秒内说明 7 天身体拼图价值
- [ ] 是否明确每天只需标准拍照和饭后反馈
- [ ] 是否避免复杂商业故事
- [ ] 是否明确非医疗建议边界

## 3. 建档页评审

- [ ] 字段是否控制在 20 个以内
- [ ] 必填字段是否足够少
- [ ] 是否 3 分钟内可完成
- [ ] 是否没有收集体检报告、硬件数据等高负担信息

## 4. 标准拍照页评审

- [ ] 用户是否 10 秒内理解拍照规则
- [ ] 是否只要求单拍，不要求双拍或称重
- [ ] 图片失败、重拍、继续提交状态是否清楚
- [ ] 饮料 / 加餐可选记录是否不干扰主流程

## 5. AI 即时分析页评审

- [ ] 是否只输出范围化结构判断
- [ ] 是否没有展示精确卡路里或精确克数
- [ ] 风险提示是否使用可能性表达
- [ ] 低置信度和失败兜底是否明确
- [ ] 文案是否不制造焦虑

## 6. 饭后反馈页评审

- [ ] 是否 8 秒内可完成反馈
- [ ] 是否不要求长文本
- [ ] 未到时间、可反馈、错过状态是否清楚
- [ ] 反馈后是否让用户感到数据有价值

## 7. 单餐档案页评审

- [ ] 是否能看懂本餐为什么被记录
- [ ] 结构分析和饭后反馈是否关联清楚
- [ ] 是否没有变成复杂报表
- [ ] 可选剩余量校准是否不阻断主流程

## 8. 身体拼图报告页评审

- [ ] 是否说明有效餐次和数据可信度
- [ ] 是否输出个人化规律，而不是泛泛健康建议
- [ ] 是否覆盖风险组合、安全食物和下周建议
- [ ] 数据不足状态是否能推动继续记录

## 9. 餐前抽卡雏形评审

- [ ] 安全牌 / 风险牌是否来自用户已记录规律
- [ ] 是否避免完整餐单托管
- [ ] 采纳 / 跳过反馈是否足够轻
- [ ] 是否能验证用户是否愿意让渡一点决策权
